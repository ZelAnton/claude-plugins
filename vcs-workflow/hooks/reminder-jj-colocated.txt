[vcs-workflow] New user prompt (jj-colocated repo) — before any edits, evaluate the change scope (and when pushing, the target bookmark):

1. Run `jj st` to see the current change description.
2. Classify this prompt:
   - **Continuation**: same topic, refinement, or follow-up of in-progress work → just work; jj folds edits into current change.
   - **Scope shift**: same change, but the goal has been refined or expanded → `jj describe -m "<refined summary>"`.
   - **New work**: orthogonal topic or different area → `jj new -m "<concise summary>"` (descendant) or `jj new @- -m "..."` (sibling if current work is unfinished).
3. If unclear which category this prompt falls in, ask the user before editing.
4. Pushing — target the active bookmark's upstream, never `main` by default:
   - The active bookmark is the nearest bookmark in `::@` (`jj log -r 'heads(::@ & bookmarks())' -T 'bookmarks'`) — the branch this work belongs to.
   - Advance it when ready (`jj bookmark move <name> --to @`) and push only it: `jj git push -b <name>` (goes to that bookmark's own upstream).
   - Touch `main` only if `main` itself is the active bookmark. If the work belongs on a feature branch, set/create that bookmark instead of advancing `main`.
5. This repo is colocated: drive version control through `jj`, not raw `git`. Git writes (`git commit`/`checkout`/`reset`) can desync the jj working copy; if one is unavoidable, follow it with `jj git import`.
